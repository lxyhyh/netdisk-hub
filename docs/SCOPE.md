# 范围（SCOPE）

- 状态：草案 v0.1
- 产出任务：T-001
- 最后更新：2026-11-26

## 1. 本阶段（阶段 0）允许做什么

- 建立项目控制面文档
- 建立 APK / 资料索引
- 只做接口侦察与线索记录，不做完整接口还原
- 记录待确认问题

## 2. 本阶段明确不做什么

- 不写生产业务代码
- 不接真实网盘接口
- 不提交真实账号 / token
- 不把 reverse/ 产物加入 Git
- 不一次性深入全部 9 个网盘

## 3. 范围变更规则

1. 新增依赖、改架构、扩大范围，**必须先写 ADR 提案**，等批准后才执行。
2. ADR 放在 docs/ADR/。
3. 未经批准的变更不得静默实施。
4. 范围变更必须同步更新本文件与 TASKS.md。

## 4. MVP 范围冻结

冻结内容：

- Android 客户端 + 多账号
- 统一文件列表 / 搜索
- 下载 / 上传 / 重命名 / 删除 / 新建文件夹
- 任务队列
- 先 2 个网盘跑通

冻结之外的任何功能，一律进 backlog，不进 MVP。

## 5. 非目标

**登录相关非目标：**

- OAuth 第三方授权
- 跳转浏览器授权后回调
- WebView 登录
- cookie 提取
- token 手动导入
- 网页端会话复用
- 任何间接授权或被动获取凭证的方式

**功能相关非目标：**

- 分享站、同步盘、在线预览、跨盘秒传、自动备份、多租户、商用
- 高保真视觉稿、自定义设计系统、动效规范（见 docs/design/UI_DIRECTION.md）

## 6. 兜底策略

**登录兜底策略：**

经侦察确认原生登录不可行（只能 OAuth/WebView/cookie）的网盘，
标为“暂不支持”，从 MVP 移除。
不采用 OAuth、WebView 登录、cookie 提取、token 手动导入作为替代方案。
不得静默降级为间接登录方案。

**资料缺失的兜底策略：**

现有 APK 无法支撑官方协议还原（第三方客户端 / 载荷不符 / 只是子模块）的网盘，
按 T-001 拍板结论标为 **“资料缺失、原生登录不可行”**，从 MVP 移除。

- **不硬凑**：不拿第三方客户端协议冒充官方协议
- **不降级**：不得因此改用 OAuth / WebView / cookie / 手动 token
- **可重开**：若日后补充官方 APK 或网页端资料，可重开任务重新判定

当前命中此条的网盘：**蓝奏云、UC 网盘、迅雷云盘**（见 docs/PROVIDERS.md §3）。

## 7. 分阶段质量门禁表

| 门禁项 | 阶段 1 | 阶段 2 | 阶段 3+ |
|---|---|---|---|
| CRAP | CI 硬门禁 ≤6 | ≤6 | 目标 ≤4，CI 硬门禁 ≤4 |
| Kotlin 变异测试 | 不强制 | 核心模块 ≥90%，存活变异体全部 triage | Provider 核心模块目标 100%，等价变异体显式抑制并写明理由，CI 对未 triage 存活体报错 |

| lint / typecheck / test | 必须全绿 | 必须全绿 | 必须全绿 |

说明：**100% 变异覆盖率不是阶段 1 的硬门禁**，阶段 1 只卡 CRAP ≤6 与测试全绿。
