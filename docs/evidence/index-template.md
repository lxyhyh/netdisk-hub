## 硬性规矩（不可删改）

1. **每条线索必须带 `文件:行号` 定位。** 这是格式能立住的核心。
2. **可信度只用三档**：已验证 / 推测 / 待确认。「已验证」= 在反编译产物中读到了这段代码/常量，**不表示服务端行为已验证**。
3. **「未发现」必须写明搜索方式**（grep 关键词、搜索范围），否则无法区分「搜了没有」和「没搜」。
4. **无证据不得写成事实**，缺资料写「待确认」并说明缺什么。
5. **覆盖率必须按 dex `class_defs` 算**，且「内联」要计入覆盖（见 §2.1）。

### 1.1 【新增①】主体技术栈判定的写法

**这三种判定直接决定后续投入，必须写清楚：**

**A. `Java/Kotlin 主体`** —— 业务逻辑在 dex 里，静态反编译有实际价值。无 libflutter.so、无 libapp.so，dex 内有完整的网络层/业务层类。

**B. `Flutter 主体`** —— 业务逻辑编译进 `libapp.so`（Dart AOT 快照），dex 里只有入口壳与原生桥接。必须在 §1 下方**紧跟一句加粗声明**：

> **⚠ 本文对网盘协议的覆盖为 0。** 业务逻辑在 `libapp.so`（Dart AOT），jadx 反编译 dex
> 只能得到入口壳、原生桥接方法名、插件注册表与资源文件。§3–§8 预计全部为「dex 内未发现」。

**C. `NestedWeb 主体`** —— 网盘功能是 H5，原生壳只是浏览器容器。同样需声明覆盖有限，并说明 H5 资源是否被打包在 APK 内（若在，可能从 assets 里拿到 JS）。

### 2.1 【新增②·必填】反编译覆盖率

**口径必须先写清再写数，不许只给百分比。**

| 项 | 值 | 来源 |
|---|---|---|
| dex 内目标包类定义总数（含 `$` 的类） | | 纯 python 解析 dex `class_defs` 表，见下 |
| jadx 主产物独立文件 | | `find sources -name '*.java'` |
| 二次补出独立文件 | | `--single-class` 补出目录 |
| 内联在外层文件中 | | 产物内 `// from class: a.b.C.1` 命中 |
| 外层文件中的成员类声明 | | 如 `R$anim` → `R.java` 的 `class anim` |
| synthetic 空类 | | `ACC_SYNTHETIC` 且方法数 0 |
| **仍未定位** | | |
| **覆盖率** | | (总数 − 仍未定位) / 总数 |
| **【必填】缺失类是否影响核心链路** | `是` / `否` / `待确认` | 见下方判定标准 |
| 缺失类清单 | `reverse/<网盘名>/jadx-missing.log` | 脚本输出 |
| 缺失原因 | | jadx 日志；未保留则写「待确认」 |
| 复现脚本 | `reverse/<网盘名>/coverage-check.py` | 纯 python 解析 dex |

**统计口径（照坚果云 §2.1.1 抄，不要自己想）**

- **分母** = dex `class_defs` 里所有目标包前缀的类定义，**含 `$` 匿名/内部类**。只按不含 `$` 的类算会漏掉 jadx 内联的主要对象，得出假缺失。
- **判定顺序**（命中即归类，不重复计入）：`file-main` → `file-rec` → `nested-decl-in-outer` → `synthetic-empty` → `inline-anon-comment` → `missing`
- **「内联」的含义**：jadx 默认把匿名内部类/lambda/枚举 switch 映射类展开进宿主方法体，只在 `new ...() {` 行尾留注释 `// from class: <点号形式类名>`（注意是**点号** `.1` 不是 `$1`）。这种类「没有独立文件」但**代码在**，必须算作覆盖。
- **`synthetic-empty` 不是失败**：`ACC_SYNTHETIC` 且方法数 0 的类，jadx 输出 0/1 字节空文件是正确行为。

**「缺失类是否影响核心链路」的判定标准：**

- **是** —— 缺失类里有网络层/认证/文件操作相关类。必须在正文中逐个列出，并用 `--single-class` 补出。**未补出前，相关章节必须写「覆盖不全」。**
- **否** —— 缺失类全部是 UI、动画、未使用的第三方库，或已证实为零业务逻辑的 synthetic/伴生类。可列出名单后放行。
- **待确认** —— 缺失类太多、或分类不清，无法逐个判断。

**每个网盘都必须实际算这个数，不许写「估计 100%」。**

参考（坚果云，口径 v2）：dex `class_defs` 内 2753 个类定义，覆盖 2752 个 = 100.0%（唯一未定位类零业务逻辑）。旧版「2019 类 / 产出 1912 / 缺 107（5.3%）」为统计口径错误，**不要照抄旧数字**，详见 `index-坚果云.md` §2.1.1。

**反编译命令必须带日志重定向**，否则缺失原因不可复现：

```bash
./reverse/_tools/jadx-<版本>/bin/jadx --no-res --no-imports -j 4 \
  --log-level debug -d reverse/<网盘名>/sources "<apk>" \
  > reverse/<网盘名>/jadx-full.log 2>&1
```
