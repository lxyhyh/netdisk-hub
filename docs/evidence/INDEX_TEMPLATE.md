## 硬性规矩（不可删改）

1. **每条线索必须带 `文件:行号` 定位。** 这是格式能立住的核心。
2. **可信度只用三档**：已验证 / 推测 / 待确认。
   - 「已验证」= 在反编译产物中读到了这段代码/常量
   - **不表示服务端行为已验证**
3. **「未发现」必须写明搜索方式**（grep 关键词、搜索范围），否则无法区分"搜了没有"和"没搜"。
4. **无证据不得写成事实**，缺资料写「待确认」并说明缺什么。

- 反编译产物：`reverse/<目录名>/`（不进 Git）
- 可信度取值：**已验证**（代码/资源中直接读到并核对）、**推测**（有间接证据但未闭环）、**待确认**（只看到线索，未证实）

> 本文只记录线索，不确认完整接口能力。所有"已验证"均指"在该版本 APK 的反编译产物中读到了这段代码/这个常量"，**不代表服务端行为已被验证**。

### 1.1 【必填】主体技术栈判定的写法

**这三种判定直接决定后续投入，必须写清楚：**

**A. `Java/Kotlin 主体`** —— 业务逻辑在 dex 里，静态反编译有实际价值。
无 libflutter.so、无 libapp.so，dex 内有完整的网络层/业务层类。

**B. `Flutter 主体`** —— 业务逻辑编译进 `libapp.so`（Dart AOT 快照），dex 里只有入口壳与原生桥接。

必须在 §1 下方**紧跟一句加粗声明**：

> **⚠ 本文对网盘协议的覆盖为 0。** 业务逻辑在 `libapp.so`（Dart AOT），jadx 反编译 dex
> 只能得到入口壳、原生桥接方法名、插件注册表与资源文件。§3–§8 预计全部为"dex 内未发现"。

**C. `NestedWeb 主体`** —— 网盘功能是 H5，原生壳只是浏览器容器。
同样需声明覆盖有限，并说明 H5 资源是否被打包在 APK 内（若在，可能从 assets 里拿到 JS）。

| **【必填】缺失类是否影响核心链路** | `是` / `否` / `待确认` | 见下方三个档位的判定标准 |
| 缺失原因 | | jadx 日志；未保留则写「待确认」 |

**「缺失类是否影响核心链路」的判定标准：**

- **是** —— 缺失类里有网络层/认证/文件操作相关类（如坚果云的 `RemoteFileDownloader`）。
  必须在正文中逐个列出，并用 `--single-class` 补出。**未补出前，相关章节必须写"覆盖不全"。**
- **否** —— 缺失类全部是 UI、动画、未使用的第三方库，且与 §3–§8 无关。可列出名单后放行。
- **待确认** —— 缺失类太多、或分类不清，无法逐个判断。

**每个网盘都必须实际算这个数，不许写"估计 100%"。**

坚果云实测：**2019 个类 → 产出 1912 个 → 缺 107 个（5.3%）**，其中恰好有下载核心类。
**jadx 覆盖率不是 100%，这个字段是必需的。**

### 9.1 【③必填】加固 / 风控 SDK 清单

**不只写"有没有壳"，还要列 APK 里带的第三方安全 SDK 名字、数量与版本。**

| SDK | 文件 / 包名 | 数量 | 影响 |
|---|---|---|---|
| 例：阿里聚安全 | `libsgmainso*.so`、`com.alibaba.wireless.security` | 4 | 请求签名可能是 native 实现 |
| 例：腾讯 TBS 浏览服务 | `assets/webkit/` | 1 套 | 仅 WebView 内核，多半与协议无关 |
| 例：Bugly | `libBugly_Native.so` | 1 | 崩溃上报，与协议无关 |

**判定标准**：

- 「有风控 SDK」≠「协议不可还原」，但意味着签名可能在 native 层 → 难度上升
- 「无任何安全 SDK」是本项目最希望看到的结果，要明确写出来（坚果云属于这一类）
- 不确定是否影响协议的，写「待确认」并说明需要看哪一层
